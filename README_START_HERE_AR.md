# NatureCare Ledger — تطبيق أندرويد للإدارة والمورد

هذا مشروع Android Studio جاهز لاستخراج **ملفَي APK مستقلين** من نفس مصدر الكود:

- **NatureCare | Louay** — تطبيق الإدارة، يفتح `https://relaxed-truffle-b202b1.netlify.app/owner.html`.
- **NatureCare | Supplier** — تطبيق إبراهيم، يفتح `https://relaxed-truffle-b202b1.netlify.app/supplier.html`.

## ما الذي يعمل؟

يستعمل التطبيقان WebView أندرويد لعرض **نفس تطبيق NatureCare Ledger v5 المنشور** على Netlify، بما فيه:
- التسجيل باستخدام حسابَي Supabase الحاليين.
- الفواتير والدفعات والمصاريف والمسحوبات.
- اعتماد الطرف المقابل، تحديث الرصيد والمزامنة عبر الإنترنت.
- سعر الصرف من SP Today عند إنشاء حركة جديدة، بواسطة الوظيفة المنشورة في Supabase.
- حفظ كشف حساب CSV عبر واجهة الملفات في أندرويد، والطباعة، ونسخ رمز الدعوة.

**لن تحتاج وضع مفاتيح Supabase أو SP Today في مشروع أندرويد:** الربط قائم بالفعل على الموقع والخادم. لا تضع كلمات مرور أو مفاتيح سرية هنا.

**ملاحظة تنفيذية:** هذان تطبيقان أندرويد قابلان للتثبيت (APK) يعرضان واجهة موقعك الحالية عبر WebView، وليسا إعادة كتابة أصلية كاملة للواجهة بـ Flutter. يلزم اتصال بالإنترنت للعمل والمزامنة. تحديث واجهة Netlify سينعكس عادة داخل التطبيقين تلقائياً.

## أسرع طريقة لاستخراج ملفَي APK من دون تثبيت أدوات بناء أندرويد

1. أنشئ مستودع GitHub جديداً، والأفضل جعله **Private**.
2. ارفع **محتويات مجلد المشروع نفسه** إلى جذر المستودع، مع المحافظة على المجلد المخفي `.github/workflows` وملف `build-apks.yml` داخله.
3. من GitHub افتح **Actions** ثم اختر **Build both NatureCare Android APKs** واضغط **Run workflow**.
4. بعد نجاح البناء افتح التشغيل، وانزل إلى **Artifacts** وحمّل ملفَي:
   `NatureCare-Louay-APK` و `NatureCare-Ibrahim-APK`.
5. فك ضغط كل ملف Artifact، وستجد APK يمكن نقله إلى موبايل أندرويد وتثبيته.
6. لإكمال التثبيت قد يطلب أندرويد السماح بالتثبيت من هذا المصدر؛ فعّل السماح فقط للمصدر الموثوق الذي نقلت منه الملف.

عند أول تشغيل يدخل لؤي بحسابه الإداري الحالي، ويدخل إبراهيم بحساب المورد الحالي. **لا تنشئ جداول أو حسابات جديدة.**

## البناء باستخدام Android Studio بدلاً من GitHub

1. افتح المجلد كـ مشروع Gradle في Android Studio.
2. بعد المزامنة، من Build Variants اختر `ownerDebug` ثم Build > Build APK(s)، واحفظ ملفه.
3. غيّر إلى `supplierDebug` وكرر العملية.
4. أو استخدم الطرفية بوجود Gradle 8.7 و Android SDK 35 و Java 17:

   `gradle :app:assembleOwnerDebug :app:assembleSupplierDebug`

الملفات الناتجة ستظهر في:
- `app/build/outputs/apk/owner/debug/app-owner-debug.apk`
- `app/build/outputs/apk/supplier/debug/app-supplier-debug.apk`

## اختبار إلزامي على هاتفين قبل الاعتماد المالي

- تسجيل الدخول من كل تطبيق بحساب الطرف الصحيح.
- إنشاء فاتورة ومراجعة الطرف الآخر لها واعتمادها.
- إضافة مصاريف (+ للمورد) ومسحوبات (− من مستحق المورد).
- التحقق من قيمة الدولار التلقائية ومطابقة سعر SP Today.
- استخراج CSV وفتحه؛ اختبار الطباعة.
- قطع الإنترنت للتأكد من ظهور تنبيه عدم الاتصال بدلاً من تسجيل قيود غير محفوظة.
- اختبار استعادة الجلسة عند إغلاق التطبيق وإعادة فتحه.

## قبل التوزيع المستمر

ملفات هذا المشروع تُبنى بشكل **Debug APK** لأغراض التجربة، وتُوقّعها بيئة البناء بمفتاح تجريبي. قد يتغير التوقيع بين عمليات البناء، فتحتاج إزالة نسخة Debug السابقة لتثبيت نسخة Debug جديدة. **لا تعتمد هذا التوقيع للإصدارات النهائية**.

للإصدار النهائي يجب إعداد توقيع إصدار ثابت (Android release keystore) محفوظ بأمان خارج المستودع، مع رفع رقم الإصدار عند كل تحديث. لتوزيع التطبيق في Google Play يُفضّل إعداد AAB وإجراءات الخصوصية والاختبار المناسبة.

## الخصوصية والسلامة

- صلاحيات القراءة والتعديل تعتمد على سياسات Supabase الموجودة، وليست على الاسم أو شاشة الدخول وحدهما.
- Android WebView يحمّل فقط صفحات موقع Netlify المحدد، وأي رابط خارجي ينفتح في متصفح الجهاز.
- لم تُنسخ بيانات الحسابات أو كلمات المرور أو مفاتيح الخدمة ضمن المشروع.
- التطبيق لا يفعّل إشعارات Push أو العمل دون إنترنت تلقائياً؛ هذه ميزات مستقبلية تتطلب تطويراً إضافياً.
- اسم الموقع الحالي مثبت في `app/build.gradle`؛ إذا تغيّر نطاق Netlify، عدّل `START_URL` ثم أعد البناء.

## قيود الاختبار

تم تحضير المشروع ومراجعة ملفات المصدر محلياً؛ لم يتم تجميع APK داخل بيئة إعداد المشروع لعدم توفر Android SDK/Gradle فيها. البناء النهائي واختباره على هاتفين مطلوبان.
